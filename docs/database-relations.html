核心查询链路

用户查票只需要车站、车次和日期，不按车次号反查。

从两座车站定位同一条车次路径
两座 station 出发站 id + 到达站 id
→
两条 train_stop 确认 stop_order 方向
→
train_segment 区间 from_order ～ to_order − 1
→
余票 + 票价 ticket_stock 取 MIN；price 求和
下单：按订单的起止段区间执行条件 UPDATE，一次扣减所有覆盖段。
退票：读取订单保存的起止段区间，一次回补所有覆盖段。

表关系总览

点击任意表，突出显示与它直接关联的其他表。

账号 车次 订单 库存 管理

账号与审计

用户端和管理端账号彼此独立。

静态车次定义

一天中的停站顺序决定分段；同一车次每天复用这套定义。

用户与订单

订单保存统一行程区间，明细保存每位乘客的票和身份快照。

动态分段库存

库存是唯一按月历变化的业务表；车次和分段定义保持静态。

查票

区间所有段的 remaining_count 取最小值；所有段价格求和。

防超卖

下单执行 UPDATE ... WHERE remaining_count >= count，检查受影响段数。
