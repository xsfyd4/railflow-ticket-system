### 3. 2026-10-20：接入 MySQL 与 MyBatis

**做了什么**

- 配置 MySQL 数据源和 HikariCP。
- 选择原生 MyBatis + XML，而不是 MyBatis-Plus。
- 配置驼峰映射：`station_name → stationName`。
- 建立 Mapper + XML 的数据库访问方式。
- 增加数据库连通探针。

**解决的问题**

- Java 对象和数据库字段解耦。
- 复杂区间查询、库存条件更新可以手写 SQL。
- 避免过早依赖 MyBatis-Plus 的自动 CRUD。

**踩坑**

- IDEA 修改 Maven 依赖后需要 Reload，否则会出现程序包不存在。
- Java 代码修改后必须重启后端，Spring Boot 默认不会热加载。

### 6. 2026-10-23：完成分段库存

**做了什么**

- 新建 `ticket_stock` 分段库存模块。
- 支持按未来日期批量生成库存。
- 支持管理员查某天某车次的逐段库存。
- 支持手工调整剩余票数。


**解决的问题**

- 重新生成库存不会覆盖已售票。

**验证**

### 7. 2026-10-23：完成用户查票

**做了什么**

- 实现 `GET /api/user/tickets/search`。
- 查票参数为出发站、到达站、日期、席别和分页。
- 用两次 `train_stop` 关联确认运行方向。
- 用 `train_segment` 的区间定位所有覆盖段。
- 余票取区间内 `MIN(remaining_count)`。
- 票价取区间内 `SUM(price)`。
- 先分页车次 id，再查席别明细，避免 JOIN 放大分页结果。

**解决的问题**

- 不按车次号查票，而是按线路和日期查票。
- 避免同一车次多个席别导致分页被切碎。
- 修复 MySQL 严格模式下 `DISTINCT + ORDER BY` 的业务码 3065 错误。
- 反向站点查询返回 0，不会误卖反向票。

**验证**

- 北京南到上海虹桥能查到 G1001 等车次。
- 多段库存中某段余票最少时，区间余票正确取最小值。

### 9. 2026-10-23：完成订单创建与防超卖

**做了什么**

- 建立订单主表和订单明细模块。
- 实现 `POST /api/user/orders`。
- 校验乘车人归属和重复。
- 后端重新计算站序、段号、价格和总金额。
- 用条件 UPDATE 原子扣减整个区间的所有分段库存。
- 库存、订单主表和订单明细在同一事务中提交。
- 生成待支付订单、订单号和 15 分钟支付截止时间。

**解决的问题**

- 前端无法篡改金额或缩短扣库存区间。
- 任意一段余票不足时，整个事务回滚。
- 两个线程同时抢最后一张票时只有一个成功。

**设计修正**

- 最初设计了 `order_segment`，每张票每段写一行。
- 评估后发现当前订单所有乘客共享同一区间，直接使用订单主表的起止段字段即可。
- 删除 `order_segment` 实体、SQL、数据库表和文档，避免无意义的数据膨胀。

**验证**

- 正常下单扣减全部覆盖段。
- 中间段余票不足时，前面已扣库存全部回滚。
- 并发抢最后一张票不会超卖。

### 10. 2026-10-23：完成订单列表、详情、支付与取消

**做了什么**

- 实现当前用户订单分页列表。
- 实现按订单号查询订单详情。
- 查询必须同时带 `user_id + order_no`，防止越权。
- 订单详情的乘车人证件号脱敏。
- 实现模拟支付：`待支付 → 已支付`。
- 实现取消订单：`待支付 → 已取消`。
- 取消时按订单起止段区间回补库存。
- 使用 `SELECT ... FOR UPDATE` 锁定订单行。
- `markPaid`、`markCancelled` 同时带 `status=0` 条件。

**解决的问题**

- 重复支付失败。
- 已支付订单不能取消。
- 超时订单不能支付。
- 其他用户不能查看或支付订单。
- 重复取消和并发取消不会重复回补库存。

**验证**

- 支付、取消、库存恢复、越权和并发取消测试通过。

### 12. 2026-10-23：完成支付超时自动取消

**做了什么**

- 开启 Spring `@Scheduled`。
- 每分钟扫描最多 100 个到期待支付订单。
- 每个订单使用独立事务处理。
- 处理前通过 `FOR UPDATE` 重新锁定订单。
- 再次确认订单仍为待支付且确实已过期。
- 回补订单覆盖的全部库存。
- 修改订单为已取消并记录 `cancelled_at`。
- 增加 `(status, expire_time)` 索引，避免扫描过期订单时扫整张订单表。
- 单个订单失败只记录日志，不影响同批其他订单。

**解决的问题**

- 用户下单后不支付时，库存不会永久占用。
- 支付、用户取消、定时任务并发操作同一订单时，行锁保证状态串行变化。
- 过期任务重复扫描不会重复回补库存。
- 已支付或未过期订单不会被误取消。

**验证**

- 过期订单自动取消并回补库存。
- 同一过期订单再次处理时不会重复回补。
- 未过期订单和已支付订单不会被取消。

### 13. 2026-10-23：完成部分退票与全部退票

**做了什么**

- 新增 `POST /api/user/orders/{orderNo}/refund`。
- 退票请求使用 `orderItemIds` 选择具体乘客的票。
- 订单状态调整为：
  - `3 = 部分退票`
  - `4 = 全部退票`
- 订单明细增加单票退票状态和 `refunded_at`。
- 订单主表增加累计退款人数、退款金额和最后一次退款时间。
- 退票时锁定订单和选中明细，再按本次退票人数回补区间库存。
- 根据剩余有效明细自动计算部分退票或全部退票。

**解决的问题**

- 支持两位乘客只退其中一位。
- 部分退票后订单状态和每张票状态能够同时正确表达。
- 重复退同一张票不会重复回补库存。
- 并发退同一张票只有一个请求成功。
- 不支持退别人的订单，也不允许待支付订单直接走退票。

**验证**

- 两位乘客先退一张，订单为部分退票，每段只回补一张。
- 再退剩余一张，订单变为全部退票，库存完整恢复。
- 重复退票、并发退票、越权退票和待支付退票均被拒绝。

## 已解决的关键工程问题

| 问题 | 解决方案 |
| --- | --- |
| 用户 token 调管理端接口 | 管理端拦截器校验 `role=ADMIN` |
| 密码明文 | BCrypt |
| 车站和车次唯一性 | 应用层查重 + 数据库唯一索引 |
| 停站乱序 | 使用 `stop_order`，禁止按 id 排序 |
| 修改停站与已有库存冲突 | 有库存时拒绝修改 |
| 查票车次分页被席别放大 | 先分页车次 id，再查席别 |
| 多段余票计算 | 对覆盖段取 `MIN` |
| 多段票价计算 | 对覆盖段求和 |
| 并发超卖 | 事务 + 条件 UPDATE + 检查影响行数 |
| 用户越权操作乘车人/订单 | SQL 同时带当前 `user_id` |
| 重复取消导致库存重复回补 | 订单行锁 + 状态条件更新 |
| 未支付订单永久占库存 | 定时扫描过期订单并自动取消 |
| 订单占段表数据膨胀 | 删除 `order_segment`，使用订单起止段区间 |
