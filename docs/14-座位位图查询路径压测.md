# 14 · 座位位图查询路径压测

## 测试目的

比较本地车段车次哈希索引和 Redis 查票对象分别对查询性能的贡献，并测试清空 Redis 后的冷缓存预热效率。

## 测试环境

- 后端：Spring Boot 4.1.1，Java 17
- 数据库：MySQL，110 个车站、1,000 个车次、284,400 条库存
- Redis：cache 组 1 Master + 2 Replica，stock 组 1 Master + 2 Replica
- 压测场景：北京南到上海虹桥，2026-11-26，二等座，第一页
- 压测并发：64
- 每组持续：20 秒
- 压测工具：`scripts/max_load_test.py`

所有场景使用相同数据库、Redis、JVM、连接池和查询参数。每组测试前清理对应缓存，避免上一组污染下一组。

## 四组 QPS

| 场景 | Redis 查票对象 | 本地哈希索引 | QPS | P50 | P95 | P99 | 失败数 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| 无索引、无 Redis | 否 | 否 | 2,070.66 | 28.11ms | 54.99ms | 78.18ms | 0 |
| 无索引、有 Redis | 是 | 否 | 8,714.24 | 2.42ms | 10.45ms | 18.78ms | 0 |
| 有索引、无 Redis | 否 | 是 | 3,459.03 | 16.75ms | 34.50ms | 50.33ms | 0 |
| 有索引、有 Redis | 是 | 是 | 8,633.55 | 2.42ms | 10.68ms | 19.43ms | 0 |

## 结论

### 1. 索引在没有 Redis 时提升明显

```text
2,070.66 QPS → 3,459.03 QPS
提升约 67.05%
```

同时：

```text
P99：78.18ms → 50.33ms
降低约 35.62%
```

原因是慢查询需要执行三次数据库查询，而索引路径只需要通过 HashMap 找到车段，再执行一次座位位图批量查询。

### 2. Redis 命中时索引影响几乎消失

```text
无索引、有 Redis：8,714.24 QPS
有索引、有 Redis：8,633.55 QPS
```

差约 `0.93%`，属于单次压测波动。Redis 查票对象已经直接返回完整页结果，不再访问本地索引或数据库，因此热缓存路径不会因为索引开关产生明显变化。

### 3. Redis 对有索引路径提升最大

```text
有索引、无 Redis：3,459.03 QPS
有索引、有 Redis：8,633.55 QPS
提升约 149.59%
```

这说明索引解决的是 Redis 未命中后的数据库回源效率，而 Redis 解决的是重复热点查询不访问后端数据库的问题。

### 4. 完整链路相对慢查询

```text
2,070.66 QPS → 8,633.55 QPS
提升约 316.95%

P99：78.18ms → 19.43ms
降低约 75.15%
```

## 索引对 Redis 冷缓存预热的影响

Redis 服务本身的启动时间与业务索引无关。这里测试的是应用启动后，清空 cache Redis，再生成 240 个热门查票对象所需的时间。

| 场景 | 预热对象数 | 预热耗时 |
| --- | ---: | ---: |
| 无索引 | 240 | 2,675ms |
| 有索引 | 240 | 1,517ms |

有索引时预热耗时降低：

```text
(2,675 - 1,517) / 2,675 = 43.29%
```

速度约为无索引时的：

```text
2,675 / 1,517 = 1.76 倍
```

索引减少了每个缓存对象首次生成时的三阶段数据库查询，因此可以更快完成 Redis 冷启动预热。

## 注意事项

- 压测客户端、后端、MySQL 和 Redis 运行在同一台电脑上，结果用于版本间横向比较，不代表生产服务器容量。
- 当前只测试单一热点站对。更完整的论文实验应再增加多站对混合流量和 16、32、64、128 并发阶梯测试。
